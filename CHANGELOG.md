# Changelog

## 4.4.1 — 2026-11-16

### Fixed
- The executive summary counted the same page several times when tools reported it with and without a trailing slash or with a `:`/`:<line>` suffix (for example "across 15 pages" for a 6-page sample). Pages are now counted once.
- PDF cover: "Generated by" is now "Tested with" (the version that ran the checks).

## 4.4.0 — 2026-11-16

### Added
- **PDF report** (`--format pdf`, now in the default `json,md,html,pdf`; `ada-audit report <dir> --format pdf` rebuilds it from an existing run). Headless Chromium renders the HTML report in print mode with `page.pdf`: a cover (site, date, standard, scope, result, methods, limits and disclaimer), the plain-language summary with screenshots of the top 3 barriers, the fix plan, the findings table (header row repeats), one card per finding with fix steps, effort and how to verify, then not-tested items, the manual checklist and the evaluation statement. Page numbers in the footer.
- `--paper a4|letter` (config `paper`, default `a4`).
- Accessible as far as Chromium allows: tagged PDF (structure tree from the HTML, `/Lang (en)`, title, headings, tables, figures with alt text) plus bookmarks from the headings. Rendering is local and read-only: JavaScript off, service workers blocked, every non-`file:` request aborted.
- API: `writeAllReports()` (async, all formats) and `writePdf()`; `writeReports()` stays synchronous and rejects `pdf`. Types updated.
- `docs/sample-report/report.pdf` (fictional checkout fixture); `test/e2e/pdf.test.mjs` (tagging, language, title, outline, A4/Letter, alt text, no temp files, axe-clean print HTML) and unit tests for the print HTML and `--paper`.

### Changed
- `ada-audit sr` keeps `json,md,html` by default; add `pdf` with `--format`.

## 4.3.0 — 2026-11-16

### Added
- `ada-audit sr --url <url> [--journey file]`: drives **real NVDA (Windows) or VoiceOver (macOS)** with Guidepup 0.40 through a journey (headings, landmarks, form fields, buttons, links, graphics, Tab), records every spoken phrase to `real-sr/<sr>-<browser>-<page>.json|txt`, and maps problems into findings with method `real-screen-reader`, separate from the simulated `sr-transcript`. Options: `--sr`, `--browser`, `--max`, `--pass-timeout`, `--page-timeout`, `--dry-run`, `--format`. Read-only: nothing is activated or submitted and non-GET requests are aborted, so error announcements are reported as not tested.
- `.github/workflows/screen-readers.yml` (*Real screen readers*): NVDA + Chromium on windows-2025 and VoiceOver + WebKit on macos-15, then merges both with the Linux suite, validates, and scores against the W3C BAD answer key in the job summary.
- New rule family `real-sr` (no heading, empty heading, no main, no bypass, unlabeled field, unnamed button/link, file-name alt or link text, vague link, duplicate link names to different targets, missing alt, focus removed, focus changes context, repeat).
- `bench/bad-home-answer-key.json`, `bench/bad-journey.json` and `scripts/bench-bad.mjs` (per-method recall and after-page false-positive candidates).
- `docs/real-screen-reader.md`; report section "5a. Real screen-reader runs"; API exports `parsePhrase`, `analyzeTranscript`, `realScreenReaderRuns`.

### Changed
- Findings schema **1.1.0** (additive): `methods[]` per finding, `method` per evidence item, top-level `realScreenReader[]`, `run.versions.guidepup` / `realScreenReaders`.
- Reports no longer say "no real screen reader was used" when real-SR transcripts are merged; the manual checklist then asks for a human listening check instead of a first screen-reader pass.

### Benchmark
W3C BAD before/home (18 A/AA failures): real NVDA 8/18, real VoiceOver 5/18, simulated SR 3/18, axe 7/18, suite 16/18 with or without real SR; real SR raised nothing on the after page. Run: https://github.com/eedgarivann/ada-audit-scripts/actions/runs/43809005716

## 4.2.1 — 2026-11-15

### Added
- The sample report (`npm run sample-report`) now comes from a live, read-only run against the local fictional checkout fixture. It includes screenshots: element crops of focused controls, viewport and journey captures, copied into `docs/sample-report/screenshots/`.
- Each finding card in Markdown and HTML now shows its most specific screenshot (element crop first, narrowest width first), with alt text and a caption.
- Tab-walk findings now link the crop of the stop that was flagged.
- `docs/platform-hints.md` lists the official vendor sources for the WordPress, Shopify, Webflow, Framer, Squarespace, Wix and React hints, checked 2026-11-15. Report cards link to it.
- npm-ready package: explicit `files`, `bin`, `prepublishOnly` (check + tests) and `publishConfig`. It is not published to the registry; install with `npx github:eedgarivann/ada-audit-scripts#v4.2.1`.

### Changed
- Platform hints were corrected against vendor docs:
  - Shopify, Webflow, Framer and Squarespace alt-text paths.
  - Framer site language.
  - Squarespace focus outline (built in).
  - Wix focus and skip link (Accessibility Wizard).
  - WordPress core skip link in block themes.
  - React page title.
- Lint is now clean (0 warnings, 0 errors) and CI fails on any warning (`--max-warnings 0`). Unused variables were removed from journeys; no behaviour change.

## 4.2.0 — 2026-11-15

### Added
- Unified `ada-audit` CLI: run, report, validate, tools, rules; JSON config, named critical user journeys, platform hints, severity CI gate and documented exit codes.
- Versioned findings schema v1 (JSON Schema 2020-12) and ESM API with TypeScript declarations. Adapters preserve the v4 raw output, normalize rule codes and axe JSON, deduplicate across tools/pages and assign deterministic fingerprints.
- Explicit severity, confidence, A/AA vs AAA/best-practice/advisory kinds, impact, evidence, WCAG references, fix priority, effort, numbered resolution, before/after code, platform hints and verification for every finding.
- Executive/fix-plan Markdown and accessible, script-free HTML reports, SARIF 2.1.0 and CSV.
- Shared Chromium browser server, bounded job pool, per-URL sharding, navigation retry/backoff, job timeouts/retry and per-job timing/logs.
- Unit and end-to-end suites (original 32 fixture checks preserved), fictional bad/fixed checkout fixtures, reproducible sample report, CI on Node 20/22/24, lint/format configuration, architecture/config/schema/report guides, contributor and security policies.

### Changed
- Sources moved to `src/core`, `src/tools`, `src/findings`, `src/report`, `src/cli`; all root script names remain compatibility wrappers with the same flags and raw output formats.
- Tab walk stops when it completes a circuit even after the page scrolls (viewport rect no longer makes it walk 60 repeated stops).
- Reports cross-check possible traps against completed Tab walks, avoid counting forms summaries twice and normalize `input#id` / `#id` to one location.
- WCAG A/AA failures, AAA and non-failures stay separate. Simulated SR/persona methods and not-tested/manual checks are explicitly labeled; no compliance claim.

### Performance
Offline fixture suite (same 32 assertions, same 8-vCPU machine): v4.1.0 serial 451 s → v4.2.0 concurrency 4, one browser 116 s (3.9× faster). The full E2E suite, including CLI/report checks, took 156 s. These are local measurements, not a guarantee on live sites.
